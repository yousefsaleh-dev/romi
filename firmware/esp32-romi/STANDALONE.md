# تشغيل ROMI من البورد نفسها — Plan A

لو كلمة «القائمة» أو USB flash جديدة عليك، اقرأ أولًا [دليل أول مرة هاردوير](../../docs/hardware-first-time.md). فيه الشاشة النصية نفسها وبديل الموبايل خطوة بخطوة. اختيار 8 في الأداة يرفع برنامج الباب فقط عند غياب قطع الصوت.

الكمبيوتر مطلوب **مرة واحدة لرفع الكود والإعدادات والاختبار**. بعد الرفع، الجهاز يشتغل من الكهرباء والـWi-Fi وحده. المستخدم يضغط الزرار، ROMI تسمعه وترد من السماعة وتتعامل مع السيرفر. لا يفتح أحد dashboard لبدء المحادثة.

الكود منفذ ويتبني. اختبار اتصال Gemini الحقيقي نجح من الكمبيوتر بنفس صيغة الرسائل التي تستخدمها البورد. **الميكروفون والسماعة والبورد نفسها لسه محتاجين اختبار فعلي**؛ نجاح البناء ليس إثبات جودة الصوت أو استقرار الذاكرة على ESP32.

## المختصر: هتعمل إيه بإيدك؟

**قبل ما تروح:** انشر الموقع على Vercel، اختبر الـAPI عليه، وشغّل الأداة من الكمبيوتر اللي هتستخدمه للرفع:

```powershell
.\firmware\esp32-romi\romi.ps1
```

اختار **1** لتجهيز البرامج وتحميل المكتبات الآن. كل مرة تحتاج القائمة افتح نفس الأمر تاني.

**لما تستلم القطع:**

1. وصّل الأسلاك حسب الجدول تحت، ووصّل البورد بالكمبيوتر بكابل USB بيانات.
2. من القائمة اختار **7** لاختبار المايك والسبيكر: `A` يصدر صوتًا، `M` يعرض قياس المايك وأنت بتتكلم، `T` يحرّك السيرفو. اقفل شاشة الاختبار بـCtrl+C.
3. افتح القائمة واختار **2**: اكتب اسم الواي فاي وكلمة السر ورابط موقعك وتوكن الجهاز. Enter عند سؤال الشهادة. الإعدادات تدخل في الكود تلقائيًا.
4. افتح القائمة واختار **5**: الأداة تبني الكود وتكتبه على البورد بالـUSB. انتظر رسالة SUCCESS.
5. اضغط الزرار بعد اتصال Wi-Fi: رومي تبدأ التحية وتسمعك وترد من السبيكر. ضغطة ثانية تلغي المحادثة. قبول الحجز من السيرفر هو اللي يفتح الباب.
6. افصل البورد عن الكمبيوتر ووصل USB بشاحن أو power bank؛ مصدر الـ5V بتاع السيرفو والسبيكر يفضل موصول. جرّب الزرار تاني. كده الكمبيوتر خرج من التشغيل.

لو مفيش مايك أو سبيكر، البديل في القسم 5: موبايل يقوم بالصوت. بدون ميكروفون فعلي، البورد لا تقدر تسمع الزائر وحدها.

## 1. القطع والتوصيلات

هذا الوضع لـESP32 DevKit V1 / ESP-WROOM-32 + INMP441 + MAX98357A + speaker + SG90.

| القطعة | التوصيل |
| --- | --- |
| ESP32 | USB بالكمبيوتر أثناء الرفع؛ شاحن USB أو power bank بعده |
| Servo signal | GPIO23 |
| Servo + / GND | مصدر 5V خارجي / GND مشترك |
| Push button | بين GPIO33 وGND |
| Red / Green LED | GPIO25 / GPIO26؛ مقاومة 330Ω لكل LED، الكاثود إلى GND |
| INMP441 VDD / GND / L/R | 3.3V من ESP32 / GND / GND |
| INMP441 SCK / WS / SD | GPIO14 / GPIO27 / GPIO32 |
| MAX98357A VIN / GND | 5V الخارجي / GND المشترك |
| MAX98357A BCLK / LRC / DIN | GPIO14 / GPIO27 / GPIO22 |
| Speaker | بين + و- بتوع MAX98357A؛ السالب لا يتوصل GND |
| 1000µF، rated 10V | موجب إلى 5V الخارجي، سالب إلى GND |

GPIO14 وGPIO27 مشتركان عمدًا للمايك والـamp. كل GND مشتركة. **لا توصل +5V الخارجي للـESP32 وهي USB، ولا تغذي INMP441 بـ5V.** راجع تسمية/ألوان القطعة الفعلية قبل الكهرباء.

## 2. جرّب القطع بدون سيرفر

من PowerShell داخل ROMI:

```powershell
.\firmware\esp32-romi\romi.ps1 test -Mode audio-bench
```

يرفع اختبارًا ويفتح الرسائل:

- اكتب `A`: صوت قصير من السبيكر.
- اتكلم قرب المايك ثم اكتب `M`: أرقام peak تزيد مع الكلام. يظهر slot0 وslot1 لتشخيص قناة المايك.
- اكتب `T`: السيرفو يفتح ثم يقفل.
- اضغط الزرار في هذا الاختبار: لا يبدأ جلسة إنترنت، لأنه offline.
- `Ctrl+C` يقفل الرسائل.

لو slot0 دائمًا صفر وslot1 يتغير، جرّب `MIC_LEFT_SLOT=1` في `include/romi_config.h` ثم أعد الاختبار. لو الاثنين صفر: راجع 3.3V وGND وL/R وGPIOs. لو الصوت منخفض، غيّر `MIC_GAIN` أو `SPEAKER_VOLUME_PERCENT` تدريجيًا. لو المايك/amp مختلفان عن المكونات أعلاه، wiring/gain وحدها قد لا تكفي؛ راجع نوع القطعة بدل افتراض التوافق.

## 3. اكتب الإعدادات ثم ارفع الوضع الكامل

بعد نشر Vercel واختبار API عليه:

```powershell
.\firmware\esp32-romi\romi.ps1 configure
.\firmware\esp32-romi\romi.ps1 flash -Mode full
.\firmware\esp32-romi\romi.ps1 monitor
```

configure يسألك اسم Wi-Fi 2.4GHz وكلمة السر ورابط الموقع ونفس device token الموجود على Vercel. اضغط Enter عند سؤال CA للاكتشاف الآمن. لا تدخل Gemini API key أو Supabase secret في إعدادات البورد.

### أفتح الأداة منين؟

افتح مجلد ROMI في VS Code، ثم Terminal → New Terminal، واختار PowerShell. يجب أن تكون داخل مجلد فيه `package.json` و`firmware`؛ لو أنت داخل مجلد آخر استخدم `cd` للوصول إلى مكان الـclone. شغّل الأمر الموجود فوق. لو Windows رفض تشغيل ملف ps1، نفذ في النافذة نفسها:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\firmware\esp32-romi\romi.ps1
```

كل اختيار في القائمة ينفذ خطوة ثم ينتهي؛ لإعادة فتحها شغّل نفس الأمر مرة أخرى. لو Python غير مثبت، ثبّت Python 3.11 أو أحدث مع Add Python to PATH، افتح terminal جديدًا، واختار 1. لا تحتاج Arduino IDE ولا كتابة C++.

### اسم الواي فاي هيتكتب فين؟

اختار **2** من القائمة. ستظهر الأسئلة في الـterminal واحدًا واحدًا؛ اكتب الإجابة ثم Enter:

| السؤال على الشاشة | تكتب إيه؟ |
| --- | --- |
| `WiFi SSID (2.4 GHz)` | اسم الشبكة حرفيًا، مثل اسم hotspot الموبايل |
| `WiFi password` | كلمة سر الشبكة؛ مخفية أثناء الكتابة |
| `ROMI HTTPS URL` | رابط موقعك المنشور، مثل `https://your-romi.vercel.app`، بدون `/api` |
| `ROMI_DEVICE_TOKEN` | نفس قيمة المتغير بهذا الاسم على Vercel؛ مخفية أثناء الكتابة |
| `Root CA PEM path` | اضغط Enter؛ الأداة تجلب شهادة الجذر من اتصال يتحقق منه Windows |

الأداة تحفظ الإجابات في `firmware/esp32-romi/include/romi_secrets.h`. أنت لا تدخل شبكة الواي فاي من dashboard أو من Gemini. عند الرفع، هذه الإعدادات تدخل في firmware. تغيير الشبكة لاحقًا يحتاج اختيار 2 ثم اختيار 5 مجددًا.

### التوكن بين السيرفر والبورد

على Vercel: Project → Settings → Environment Variables، المتغير اسمه `ROMI_DEVICE_TOKEN`. نفس قيمة `.env.local` إذا كنت ستستخدم إعداداتك الحالية. لو غيّرت القيمة على Vercel، اعمل redeploy، ثم أدخل القيمة الجديدة في اختيار 2 وأعد الرفع.

البورد تبعته تلقائيًا في `Authorization: Bearer ...`، والسيرفر يرفض الطلب لو القيمة مختلفة. لا تكتب توكن جديدًا عشوائيًا على البورد وحدها. `GEMINI_API_KEY` و`SUPABASE_SECRET_KEY` يظلان على السيرفر؛ البورد تحصل فقط على Gemini token مؤقت من `/api/ai/session` لكل محادثة.

### يعني إيه رفع الكود بالـUSB؟

وصّل منفذ USB الموجود على ESP32 بمنفذ USB الكمبيوتر بكابل **بيانات** مناسب للبورد. الأسلاك بين breadboard والقطع لا ترفع الكود؛ الرفع من منفذ USB الخاص بالبورد. اختيار **5** يعمل build للكود الموجود، ثم يرسل البرنامج إلى ذاكرة ESP32 عبر هذا الكابل. لو فيه بورد واحدة، المنفذ يتحدد تلقائيًا؛ لو أكثر من واحدة اختار البورد الصحيحة. انتظر SUCCESS ولا تفصل الكابل أثناء الكتابة.

اختيار **6** يفتح شاشة رسائل البورد للتشخيص. `Ctrl+C` يقفل الشاشة فقط، وليس برنامج البورد. لو الرفع واقف عند Connecting، امسك زر BOOT الصغير على البورد واتركه عند بدء الكتابة. زر BOOT يختلف عن push button استقبال الزائر على GPIO33. تفاصيل الكابل/التعريفات/الأعطال في HACKATHON.md.

`full` هو hackathon demo للباب: يعلن أن نجاح السيرفو مفترض بالزمن دون حساس. `full-safe` يستخدم الصوت نفسه لكن لا يؤكد نجاح الباب بدون تنفيذ حساس. `full -InsecureTls` متاح صراحة فقط لو شهادة موقع ROMI هي عائق عرض demo؛ اتصال Gemini يظل يتحقق من Google roots.

انتظر `[WIFI] Connected` و`[TIME] Synchronized`. اضغط الزرار:

```text
[BTN] Starting standalone voice session
[LIVE API] /api/ai/session HTTP 200
[LIVE] WebSocket connected; waiting for setupComplete
[LIVE] Active: microphone and speaker on ESP32; no dashboard required
```

تكلم. الضغطة التالية تلغي الجلسة وتوقف إرسال المايك والصوت؛ تنظيف الشبكة/تسجيل الاستخدام قد يستغرق وقت الشبكة. انتظر IDLE قبل الزائر التالي. كل جلسة لها UUID وتوكن مؤقت جديدان؛ القديم لا يُعاد استخدامه. الباب لا يتحرك بسبب الزرار نفسه، بل بسبب أمر معتمد من السيرفر.

## 4. افصل الكمبيوتر

بعد اختبار المحادثة والباب، اقفل monitor وافصل USB عن الكمبيوتر، ثم شغّل ESP32 من شاحن USB أو power bank. حافظ على مصدر 5V الخارجي وGND المشترك. اضغط الزرار مرة ثانية وتأكد من التحية والرد. هذا هو اختبار التشغيل المستقل الحقيقي.

فصل الكمبيوتر خطوة لإثبات الاستقلال؛ لو فضّلته موصولًا أثناء الاختبار عادي. البرنامج محفوظ في ذاكرة البورد، لا يحتاج terminal أو VS Code مفتوحًا. فصل الكهرباء يطفئ البورد؛ توصيل الشاحن يعيد تشغيلها، فتتصل بالـWi-Fi بنفس الإعدادات. شاحن البورد يغذي ESP32 فقط؛ السيرفو والـamp يحتاجان مصدر الـ5V الخارجي أيضًا. ما زال مطلوبًا GND مشترك دون توصيل موجب المصدر الخارجي للـESP32 وهي USB.

الجهاز مستقل عن الكمبيوتر، لكنه يحتاج الإنترنت والسيرفر وGemini. لا يعمل الصوت الذكي offline.

## 5. لو قطع الصوت مش موجودة

Plan B: **موبايل** يشغل `/dashboard/kiosk` بالمايك والسماعة بتوعه، وESP32 في `flash -Mode demo` تشغل الباب. بدء المحادثة في هذا البديل من شاشة الموبايل. مفيش افتراض إن الـPC عنده مايك. الجهاز بدون أي مايك لا يمكنه سماع الزائر؛ التشغيل الصوتي المستقل يحتاج القطع المذكورة.

تفاصيل الأعطال والكهرباء والـAPI في [HACKATHON.md](HACKATHON.md). Wokwi لا يثبت الصوت. ذاكرة classic ESP32 محدودة: الكود يستخدم buffer صغير للصوت، يستهلك الرد تدريجيًا، ويمنع تزامن تخصيص HTTPS مع استقبال إطار Gemini كبير. قياسات heap وتجربة جلسات طويلة على البورد نفسها ما زالت مطلوبة.
